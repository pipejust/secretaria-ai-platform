## Historia
Como dueño del producto, quiero que lo que el menú esconde y lo que la API permite
digan lo mismo, para que un permiso no dependa de que la pantalla no se vea.

Pedido original (reunión, Altum acten:1865): "Revisar los permisos actuales del
superadministrador y ajustarlos para corregir errores de visualización".

### Qué encontré el 2026-09-24
- Las rutas de administración del frontend cuelgan de un solo `adminGuard`, que no
  distingue administrador de superadministrador. La diferencia se hace con
  `*ngIf` en el menú, que es cosmético.
- Recorrí las 18 pantallas del panel como superadministrador: todas cargan, sin
  errores de consola y con todas las llamadas en 200.
- El caso concreto que hay que cerrar está en [[ACT-1866]] (Landing CMS).

Este ítem es la revisión transversal: recorrer cada ruta marcada como "solo
superadmin" y comprobar que el backend la exige, no solo el menú.

## Criterios de aceptación
### Happy path
- Dado el inventario de rutas del panel, cuando termino, entonces cada una declara
  qué rol exige y el backend lo hace cumplir.
### Fallo
- Dado un administrador de empresa que escribe a mano la URL de cualquier pantalla
  de superadministrador, entonces no entra y la API responde 403.
### Borde
- Dado un usuario con rol admin y `is_superadmin` en verdadero, entonces mantiene
  el acceso completo.
